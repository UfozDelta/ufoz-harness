GOAL: Add the client-side cart: a React context provider backed by `localStorage`.

CONTEXT: No backend. `storefront/lib/products.ts` exports `Product` and `products`. The provider is
mounted in the layout in a later task; the cart page and add-to-cart button consume `useCart()`.

FILES (create; touch nothing else):
- `storefront/lib/cart-context.tsx`

REQUIREMENTS:
- File starts with `"use client";`.
- `export const CART_STORAGE_KEY = "lego_cart";`
- `export type CartLine = { slug: string; quantity: number };`
- `export type CartContextValue = { lines: CartLine[]; addItem: (product: Product) => void;
  removeItem: (slug: string) => void; clearCart: () => void; itemCount: number; total: number };`
- `export function CartProvider({ children }: { children: React.ReactNode })` — holds
  `lines` in `useState<CartLine[]>([])`, hydrates once in a `useEffect` from
  `localStorage.getItem(CART_STORAGE_KEY)` (JSON parse inside try/catch, ignore bad data), and writes
  back to `localStorage` in a `useEffect` on every `lines` change.
- `addItem` increments `quantity` when the slug is already in the cart, otherwise appends
  `{ slug, quantity: 1 }`. `removeItem` drops the line entirely. `clearCart` sets `lines` to `[]`.
- `itemCount` is the sum of quantities. `total` is the sum of `price * quantity`, looked up from
  `products`, rounded to 2 decimals.
- `export function useCart(): CartContextValue` — throws
  `new Error("useCart must be used within CartProvider")` when the context is missing.
- Never touch `localStorage` during render or on the server: all storage access lives in `useEffect`
  or event handlers.

CONSTRAINTS: no state-management dependency (no zustand/redux); no analytics calls here; no edits to
pages, layout, products or analytics files; no new dependencies; never run git commands that change state.

ACCEPTANCE (run from the project root; must print `CART OK` and exit 0):
`python .harness/plans/bench-plan/checks/check_t4.py`
