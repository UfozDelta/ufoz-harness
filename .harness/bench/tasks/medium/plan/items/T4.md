GOAL: Write the pytest suite for the items API in `tests/test_items.py`.

CONTEXT: `app/main.py` exposes `app` (FastAPI), the in-memory store and `reset_store()`.
Endpoints: `GET /health`, `GET /items`, `GET /items/{item_id}` (404 `{"detail": ...}` when
missing), `POST /items` (201, returns the created item, 422 on invalid body). Ids start at 1
and increment. pytest 9.1.1 is installed; `httpx` is installed so `fastapi.testclient.TestClient`
works. Tests are run from the project root with `python -m pytest`, so `import app...` resolves.

FILES (create; touch nothing else):
- `tests/test_items.py`   (do NOT create `tests/__init__.py` or a `conftest.py`)

- Imports: `import pytest`, `from fastapi.testclient import TestClient`,
  `from app.main import app, reset_store`.
- Module-level `client = TestClient(app)`.
- An autouse fixture that gives every test an empty store:
  `@pytest.fixture(autouse=True)` def `_reset()` calling `reset_store()` before the test.
- Test functions (one assertion block each, plain `assert`, no classes):
  - `test_health`: `GET /health` -> 200 and `{"status": "ok"}`.
  - `test_list_items_empty`: `GET /items` -> 200 and `[]`.

    `{"id": 1, "name": "widget", "price": 9.5}`.
  - `test_create_then_list`: create two items, then `GET /items` -> 200, length 2, ids `[1, 2]`.
  - `test_get_item`: create one item, then `GET /items/1` -> 200 and the same body.
  - `test_get_missing_item_404`: `GET /items/999` -> 404 and `"detail"` in the JSON body.
  - `test_create_invalid_returns_422`: parametrized with `@pytest.mark.parametrize` over
    `{"name": "", "price": 1}`, `{"name": "a", "price": -1}`, `{"price": 1}`, `{}` -> each
    `POST /items` returns 422.
  - `test_store_is_isolated_between_tests`: `GET /items` -> `[]` (proves the fixture resets).
- All tests must pass.

CONSTRAINTS: match existing style; touch only the listed file; no new dependencies;
never run git commands that change state; do not modify anything under `app/` or the root `main.py`.
