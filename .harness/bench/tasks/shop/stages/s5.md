# Stage 5: Server-side cart

Read `../spec.md` first (Decisions, product table, error shape apply here). Read `s3.md`'s card
rules and validation order carefully — checkout here reuses that same logic, just fed from a cart
instead of a raw `items` list.

## What exists already
Product catalog (stage 2), mock payment gateway with `POST /api/checkout` and `GET /api/orders/{id}`
(stage 3), contact form (stage 4). Keep all of it working unchanged; `POST /api/checkout` (direct,
item-list based) must keep working exactly as stage 3 left it — the cart adds a second, separate
checkout endpoint, it does not replace the old one.

## Goal
A server-side cart (id, add/update/remove line items, totals with a shipping rule) whose checkout
reuses stage 3's card-validation and approve/decline logic.

## DB — add one table
`cart_items(cart_id INTEGER, product_id INTEGER, quantity INTEGER)`. A cart's existence is implicit
— `cart_id` is any positive integer allocated by an in-memory or DB-backed counter (e.g. a `carts`
table with just `id INTEGER PRIMARY KEY, created_at TEXT`, or reuse SQLite's rowid semantics); pick
either, the API contract below is what's tested.

## Shipping rule (fixed)
`shippingCents = 0` if `subtotalCents >= 5000` (i.e. $50+), else `shippingCents = 500` ($5 flat).
`totalCents = subtotalCents + shippingCents`.

## API (JSON everywhere, all routes export `dynamic = "force-dynamic"`)
- `POST /api/cart` → 201, creates an empty cart. `{"cartId": int, "items": [], "subtotalCents": 0,
  "shippingCents": 500, "totalCents": 500}`. (Empty-cart shipping is shown as the flat rate; it's
  moot since checkout on an empty cart is rejected — see below.)
- `GET /api/cart/{cartId}` → 200 `{"cartId": int, "items": [{"productId","slug","name","priceCents",
  "quantity","lineTotalCents"}...], "subtotalCents","shippingCents","totalCents"}`, or 404
  `{"error": "..."}` if the cart doesn't exist.
- `POST /api/cart/{cartId}/items` body `{"productId": int, "quantity": int}`. Adds the item, or
  increases quantity if that product is already in the cart. Validation, first failure wins, 400
  `{"error","field"}`: `productId` must be a known product → `field: "productId"`; `quantity` must
  be a JSON integer >= 1 → `field: "quantity"`; the resulting total quantity for that product in the
  cart must not exceed the product's current `stock` → `field: "quantity"`. Unknown `cartId` → 404
  `{"error": "..."}`. On success, 200 with the full updated cart (same shape as GET).
- `PATCH /api/cart/{cartId}/items/{productId}` body `{"quantity": int}`. Sets the quantity for that
  product (must already be in the cart). Same `quantity` validation as above (>=1, <= stock) →
  `field: "quantity"`. Unknown `cartId` or product not in the cart → 404. On success, 200 with the
  updated cart.
- `DELETE /api/cart/{cartId}/items/{productId}` → removes the item if present (no-op if absent).
  Unknown `cartId` → 404. On success, 200 with the updated cart.
- `POST /api/cart/{cartId}/checkout` body `{"customerEmail": string, "card": {"number","expiry",
  "cvv"}}`. Unknown `cartId` → 404 `{"error": "..."}`. Otherwise validate in this order (first
  failure wins, 400 `{"error","field"}`, same rules as `s3.md`):
  1. cart must be non-empty, and every line's quantity must still be <= that product's current
     `stock` → `field: "items"`.
  2. `customerEmail` format → `field: "customerEmail"`.
  3. `card.number` format + Luhn → `field: "card.number"`.
  4. `card.expiry` format + not expired → `field: "card.expiry"`.
  5. `card.cvv` format → `field: "card.cvv"`.
  On pass, create the order exactly as `s3.md` describes (same `orders`/`order_items`/`payments`
  rows, same decline card `"4000000000000002"`), but with `shippingCents` computed by this stage's
  shipping rule and `totalCents = subtotalCents + shippingCents`. **Approved**: decrement stock for
  each line, then empty the cart (delete its `cart_items` rows), respond 200 (same body shape as
  `s3.md`'s approved response). **Declined**: don't touch stock, don't empty the cart (so the buyer
  can retry), respond 402 (same body shape as `s3.md`'s declined response).

## Page: `/cart`
Client-rendered (cart id kept in `localStorage` key `nimbus-cart-id`; if absent, `POST /api/cart` on
load to create one). `data-testid="cart-page"`. If empty: `data-testid="cart-empty"`. Otherwise:
- `data-testid="cart-item"` per line, each showing name, unit price, a quantity control that calls
  the PATCH endpoint, and a remove button (`data-testid="cart-remove"`) calling DELETE.
- `data-testid="cart-subtotal"`, `data-testid="cart-shipping"`, `data-testid="cart-total"` (each
  showing `$X.XX`).
- A checkout section, `data-testid="checkout-form"`, with card number/expiry/cvv/email inputs
  (`name="customerEmail"`, `name="cardNumber"`, `name="cardExpiry"`, `name="cardCvv"`) that POSTs to
  the checkout endpoint above; on approval shows `data-testid="checkout-success"` with the order id;
  on decline or validation error shows the server's `error` message; disables the submit button
  while in flight.

## Page: `/products/{slug}` — add an "Add to Cart" control
Add a client button `data-testid="add-to-cart"` that ensures a cart id exists (creating one via
`POST /api/cart` if needed) and calls `POST /api/cart/{cartId}/items` with `{"productId": 1,
"quantity": 1}` for that product. Keep the rest of stage 2's detail page testids unchanged.
