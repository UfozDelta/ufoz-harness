# Stage 3: Mock payment gateway

Read `../spec.md` first (Decisions, product table, error shape apply here).

## What exists already
`/api/products`, `/api/products/{slug}`, `/products`, `/products/{slug}` from stage 2, backed by
`lib/db.ts`'s `products` table. Keep them working unchanged. There is no cart yet — checkout in this
stage takes the items to buy directly in the request body.

## Goal
A fully mocked payment gateway (no network calls) that validates a card, decides approve/decline
deterministically, and checks out a fixed list of items: creates an order + its line items + a
payment record, and decrements product stock on approval only.

## DB — add two tables (in `lib/db.ts`, alongside `products`)
- `orders(id INTEGER PRIMARY KEY, status TEXT, customer_email TEXT, subtotal_cents INTEGER,
  shipping_cents INTEGER, total_cents INTEGER, created_at TEXT)`. In this stage `shipping_cents` is
  always `0` (no shipping rule yet — stage 5 adds one).
- `order_items(order_id INTEGER, product_id INTEGER, quantity INTEGER, price_cents_each INTEGER)`
  — `price_cents_each` is the product's `priceCents` at checkout time.
- `payments(id INTEGER PRIMARY KEY, order_id INTEGER, status TEXT, card_last4 TEXT, created_at TEXT)`
  — `status` is `"approved"` or `"declined"`.

## Card rules (fixed, deterministic — no randomness, no clock-dependent logic besides expiry)
- `number`: strip spaces, must be 13–19 digits and pass the Luhn checksum (standard algorithm: from
  the rightmost digit, double every second digit, subtract 9 if the result is >9, sum all digits,
  valid if sum % 10 == 0).
- `expiry`: string `MM/YY`, `MM` 01–12. Treat `YY` as `2000+YY`. Invalid if the month doesn't parse
  01–12, or if the expiry year+month is strictly before the current server year+month (i.e. already
  expired). To keep tests deterministic, the decline/approve test cards below always use expiry
  `12/30` (December 2030), which is never expired in this benchmark's lifetime.
- `cvv`: exactly 3 digits.
- **Decision:** stripped card number exactly `"4000000000000002"` → **declined**. Any other
  Luhn-valid, correctly formatted number (e.g. `"4242424242424242"`) → **approved**. A Luhn-invalid
  number is a validation error (field `card.number`), never a decline.

## API
`POST /api/checkout` body: `{"items": [{"productId": int, "quantity": int}, ...], "customerEmail":
string, "card": {"number": string, "expiry": string, "cvv": string}}`.

Validate in this exact order, returning the first failure as 400 `{"error": "...", "field": "..."}`:
1. `items`: must be a non-empty array. Each entry's `productId` must be an existing product id
   (unknown id → invalid) and `quantity` must be a JSON integer >= 1. Each `quantity` must not exceed
   that product's current `stock`. Any violation → `field: "items"`.
2. `customerEmail`: trimmed, matches `^[^\s@]+@[^\s@]+\.[^\s@]+$` → `field: "customerEmail"`.
3. `card.number`: format + Luhn as above → `field: "card.number"`.
4. `card.expiry`: format + not expired as above → `field: "card.expiry"`.
5. `card.cvv`: exactly 3 digits → `field: "card.cvv"`.

If all valid, compute `subtotalCents = sum(product.priceCents * quantity)`, `shippingCents = 0`,
`totalCents = subtotalCents`. Insert an `orders` row, one `order_items` row per item, and a
`payments` row (`card_last4` = last 4 digits of the stripped number):

- **Approved**: decrement each purchased product's `stock` by its quantity. Order status `"paid"`,
  payment status `"approved"`. Respond **200** `{"orderId": int, "status": "paid", "totalCents": int,
  "payment": {"id": int, "status": "approved", "last4": "1234"}}`.
- **Declined**: do NOT change any product's `stock`. Order status `"declined"`, payment status
  `"declined"`. Respond **402** `{"orderId": int, "status": "declined", "totalCents": int, "payment":
  {"id": int, "status": "declined", "last4": "0002"}}`.

`GET /api/orders/{id}` → 200 `{"id","status","totalCents","customerEmail","items": [{"productId",
"quantity","priceCentsEach"}...], "payment": {"id","status","last4"}, "createdAt"}`, or 404
`{"error": "..."}` when missing or `id` is not a positive integer.

Both routes export `dynamic = "force-dynamic"`.
