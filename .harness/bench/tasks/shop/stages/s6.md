# Stage 6: Admin sales board

Read `../spec.md` first (Decisions, product table apply here).

## What exists already
Full storefront: catalog (s2), mock payment gateway (s3), contact form (s4), cart + cart checkout
(s5). Orders/payments come from two sources: `POST /api/checkout` (direct) and
`POST /api/cart/{cartId}/checkout` (cart). Keep everything working unchanged. This stage only adds
a read-only reporting view over the existing `orders`/`order_items`/`payments`/`products` tables —
no schema changes.

## Definitions
"Sales" counts only orders whose `status = "paid"` (i.e. the payment was approved). Declined orders
are excluded from every total below.

## API
`GET /api/admin/summary` → 200:
```
{
  "revenueCents": int,       // sum of totalCents over paid orders
  "orderCount": int,         // count of paid orders
  "unitsSold": int,          // sum of quantity over order_items belonging to paid orders
  "products": [
    {"productId": int, "slug": string, "name": string, "unitsSold": int, "revenueCents": int}
    // one entry per product, ALL 6 products always present (0/0 if never sold),
    // ordered by productId ascending. revenueCents = sum(price_cents_each * quantity) for that
    // product's line items across paid orders.
  ],
  "recentOrders": [
    {"id": int, "status": "paid"|"declined", "totalCents": int, "itemCount": int, "createdAt": string}
    // itemCount = sum of quantities in that order (not distinct product count)
    // newest first (ties broken by higher id first), limit 20, INCLUDES declined orders
  ]
}
```
Exports `dynamic = "force-dynamic"`. No auth.

## Page: `/admin`
Server-rendered from the DB (fetch the same data the API exposes, or call the API's underlying
logic directly — either way the numbers must match `/api/admin/summary` exactly).

- `data-testid="admin-revenue"` — revenue formatted as `$X,XXX.XX` (dollars with grouping, 2 decimal
  places, e.g. `$1,234.56` for 123456 cents).
- `data-testid="admin-order-count"` — the integer order count as text.
- `data-testid="admin-units"` — the integer units sold as text.
- `data-testid="admin-products"` wrapping one `data-testid="admin-product-row"` per product (6 rows,
  fixed id order), each showing the product name, units sold, and revenue (`$X.XX`).
- `data-testid="admin-recent-orders"` wrapping one `data-testid="admin-order-row"` per recent order
  (newest first), each showing the order id, status, total (`$X.XX`), and item count.
- `data-testid="admin-empty"` shown instead of the products/orders sections' content when there are
  zero paid orders (revenue/order-count/units testids still render, showing `0`/`$0.00`).

## Design
Same visual system as earlier stages. Add a nav link `<a href="/admin">Admin</a>` to the shared nav
(`data-testid="site-nav"`) without changing its other content. Apply the Design decision from
`../spec.md`; a simple table/list layout is fine, still responsive to 375px.
