Every path through the harness

What the runner does with a plan, task by task, and what each result means for you. Commands run from the repo root; run_plan.py means python .harness/run_plan.py.

01The loop

Seven steps with the main session in the middle. A failed task sends you back to Execute with a new brief; discard ends the loop.

1Decideyou + main session agree scope and success criteria
2Plan
smallmain session writes plan.md
large@planner writes it
no Claude--plan spec.md
3Approve--lint, summary + Unverified list, wait for your go
4Executerunner + executor, every task through the guards
5VerifySUMMARY.md, reports, git diff
6Decide
acceptgo to Report
re-briefback to Execute
discardstop
7ReportBlocked on me / Changed / Found, then you land and commit

02One task through the guards

No model grades its own work: every step below is the runner, not the executor. Retries and one repair pass come before a task is marked failed.

1Lock checktasks.json and checks/ hashes match the lock
matchcontinue
mismatchlock-mismatch
2Red-firstonly when red_first is on, first attempt
check failscontinue
already passescheck-invalid
3BaselineRESULT: running, file-tree snapshot, suppression counts
4Attemptexecutor runs the brief
donegrade it
exit 75rate limit, wait, rerun uncounted
exit 124timeout, fresh session retry
stray filefail at once
5Gradeacceptance ok, exit 0, no stray file, no new suppression
passnext task
failfeedback.md, retry once
6Repairafter retries run out: one pass, this task + earlier tasks' files in scope
passREPAIRED
failplan stops
7Reportitems/T<n>.report.md + metrics row

A task fails if

  • checkIts acceptance command exits non-zero.
  • scopeIt touched a file outside its files list.
  • silencedIt added @ts-ignore, @ts-nocheck or eslint-disable.
  • lockIt edited tasks.json or a check script.

The build

The full build runs once, in the last task, and never fails it. SUMMARY.md records BUILD: pass or BUILD: fail <first error> so you see it at review.

03End states

ResultMeaningWhat to do
passgraded ok, maybe REPAIREDreview the diff
failcheck, exit code, stray file or suppression after retries + repairfix the brief and rerun (passed tasks are skipped); a second fail of the same task means stop and investigate read-only
check-invalidthe check passed before any worktighten the check, rerun with --relock
lock-mismatchtasks.json or a check changedyour edit: --relock; the executor's edit: discard it
runningthe runner crashed mid-taskrerun; counts as a failed attempt, no red-first
