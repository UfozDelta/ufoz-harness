Setup

you

Copy .harness/.env.example to .harness/.env and uncomment what you change. Install pi (and opencode or the claude CLI if you use them), then check the setup with python .harness/selftest.py (one pi smoke task, $0).

The planner comes from HARNESS_PLANNER, default pi (free). Set it to claude and planning is billed even from a pi or opencode session.

1

Open terminal, start session

you
Claude Code 
cd ~/Desktop/harness-test
claude

Loads CLAUDE.md, memory and the caveman hooks automatically.

pi 
cd ~/Desktop/harness-test
node "$env:USERPROFILE\.pi\agent\bin\pi-launcher.js" `
  --no-context-files `
  --append-system-prompt .harness/MAIN.md `
  --model opencode/space-bunny-free

--no-context-files keeps the executor rules in AGENTS.md out of the main session.

opencode 
cd ~/Desktop/harness-test
opencode --agent orchestrator

opencode.json points the orchestrator agent at MAIN.md. AGENTS.md still auto-loads; MAIN.md only tells the model to ignore it.

2

Decide

you + main session

You describe the task. The main session states assumptions and success criteria and asks if anything is unclear. Nothing is written yet.

Claude runs the adhd skill first for architecture or naming decisions.

3

Plan

main session / planner
Claude Code
  • Small: writes plan.md + tasks.json in .harness/plans/<slug>/ itself.
  • Large: refreshes the repo map, then calls @planner (sonnet), which lints its own plan.
python .harness/build_map.py --check || python .harness/build_map.py
pi

Writes .harness/plans/<slug>/SPEC.md, then hands it to the planner backend:

python .harness/run_plan.py <slug> --plan .harness/plans/<slug>/SPEC.md

Writes and lints the plan, retrying twice on lint errors. Runs no tasks.

opencode

Same as pi: SPEC.md, then run_plan.py <slug> --plan.

Planner backend comes from HARNESS_PLANNER, not from which main session you use.

4

Approve

you say go
python .harness/run_plan.py <slug> --lint     # must print: lint OK

The main session shows the plan summary and its Unverified: list, then waits. Nothing runs until you say go.

5

Execute

runner + pi executor
python .harness/run_plan.py <slug>
  • Runs in its own worktree .worktrees/<slug> (branch harness/<slug>); your tree is untouched.
  • Opens a live Windows Terminal tab so you can watch.
  • One warm pi session for the whole plan. Each task: lock check → attempt → acceptance command → pass, or feedback retry, then one repair pass.
  • Touching a file outside the task's files fails it at once. Stops at the first failed task.

Claude runs it in the background and is notified when it exits.

6

Verify and fix

main session

Reads SUMMARY.md and items/T<n>.report.md in .worktrees/<slug>/.harness/plans/<slug>/, then the diff:

git -C .worktrees/<slug> diff
  • On a failure it rewrites the brief and reruns without asking; passed tasks are skipped.
  • It stops and asks you on a second failure of the same task, anything destructive, or a design question.

Under pi or opencode, Bunny does this review. It is a weaker judge of diffs than Claude, so read the diff yourself.

8

Land and commit

you only
python .harness/run_plan.py <slug> --land

Applies the worktree's changes to your main tree, copies reports and logs back, and removes the worktree and its branch. On a conflict nothing changes and land.patch is kept. No agent runs this or commits; you review and commit.

Pick Claude Code when

The work needs judgment: design calls, unclear specs, or a careful review of what the executor wrote. You pay for the main session and planning.

Pick pi when

The task is well specified and you want it free. Fastest startup, and the executor rules are cleanly kept out of the main session.

Pick opencode when

You prefer the opencode UI. Same free model as pi, but AGENTS.md still loads, so the main session sees executor rules it has to ignore.
